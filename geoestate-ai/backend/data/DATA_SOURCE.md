# Property Dataset

`properties.csv` is normalized from the user-supplied `archive (11).zip` file. The active project file contains 28,398 records and 10 columns, with amenities stored as a comma-separated text field. It does not contain numeric amenity flags or a `9` unknown sentinel. A separate analysis supplied in chat describes a 32,963-record, 40-feature dataset; that file is not present here, so its counts and findings cannot be independently verified against this active dataset. No coordinates, property images, bathroom counts, or property-type field are included in the active file, so the application must not present those as source facts.

The supplied archive did not contain a citation, dataset license, or upstream provenance. Treat the data as user-provided and do not redistribute it until its original source and reuse terms are confirmed.

## Estimator and validation

Every estimate starts with a Random Forest regression model trained on log-transformed asking prices, using location, area, bedroom count, resale status, and available amenity features. The target encoding is trained on the same transformed price scale as the forest. The model uses 120 trees, absolute-error splits, a minimum leaf size of eight, and fixed random seeds. When at least three independent listings match the city, locality, bedroom count, resale status, and area within 15%, the displayed estimate is an equal blend of the Random Forest prediction and the median comparable price per square foot scaled to the requested area. The selected property is excluded from its own comparable set. If fewer than three eligible listings remain, the estimate falls back to the Random Forest prediction. Exact duplicate source rows are removed during loading. Repeated rows with identical available model inputs are represented by their median asking price during model training; the original rows are retained for evaluation and listing display. Separate numeric amenity columns are also supported: `0` and `1` remain binary values and `9` is treated as unknown/missing, not as amenity availability.

The active dataset has no exact duplicate rows. It has 28,398 rows but only 19,911 unique combinations of the available model inputs. In 4,228 input groups with repeated rows, 8,487 rows repeat an existing input combination; some such rows have very different asking prices. This limits the maximum achievable prediction quality from the provided features alone.

Validation averages three 20% group-aware holdouts (seeds 42, 2025, and 2026). Identical input groups are kept together; test rows remain unaggregated. Each test prediction uses only its training split's comparable listings, and the selected row is excluded. The final blend/fallback estimator reports MAE INR 6,142,652 (standard deviation INR 156,821), RMSE INR 22,172,997 (standard deviation INR 2,518,607), R-squared 0.162 (standard deviation 0.003), and median absolute percentage error 30.6% (standard deviation 1.2 percentage points). The Random Forest-only baseline reports R-squared 0.157. Comparable blending improves these aggregate results only modestly and is used only when at least three eligible homes exist. The available data remains noisy and these estimates are not verified sale-price valuations.

The suggested larger forest configuration (300 trees, depth 25, minimum leaf size 2, and minimum split size 4) was tested with the same group-aware splits and training-row aggregation. Its Random Forest-only results were worse than the current 120-tree, minimum-leaf-size-8 baseline: MAE INR 6,267,931, RMSE INR 22,411,819, R-squared 0.143, and median absolute percentage error 32.9%, compared with INR 6,163,831, INR 22,236,457, 0.157, and 31.2%, respectively. It was therefore not adopted. Extreme prices are not automatically trimmed because the available data cannot reliably distinguish genuine luxury listings from data errors; metrics continue to include the full cleaned dataset.

The median absolute percentage error describes the median difference relative to a listing's asking price; it is not "accuracy." The low R-squared means the model still explains only a limited share of price variation. Do not claim that it predicts verified sale values. The evaluation measures asking prices in this supplied dataset, not verified sale-price valuations.

The source contains asking prices that are unusually high relative to other listings; the app does not silently alter source prices. Listing search accepts inclusive minimum and maximum asking-price bounds. The estimate-range action uses the model's internal validation error band to search for listings, but that band is not displayed as a property-specific confidence interval.
